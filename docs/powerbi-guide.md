# Power BI dashboard

The dashboard is a **Power BI Project** (PBIP) in [`powerbi/`](../powerbi): the data model (TMDL)
and the four report pages (PBIR) are plain text files, generated by
[`powerbi/build_pbip.py`](../powerbi/build_pbip.py), so the whole dashboard is reviewable and
reproducible like the rest of the code.

## Open it

1. Install [Power BI Desktop](https://www.microsoft.com/power-platform/products/power-bi/desktop)
   (free, Windows), a version from late 2025 or newer.
2. Open `powerbi/RetailInventory.pbip`.
3. When asked how to connect to `raw.githubusercontent.com`, choose **Anonymous**, then **Connect**.
   The model loads the CSV files from this public repo, so nothing else needs setting up.
4. Select **Refresh** if the visuals are empty.

**Offline or on your own copy?** In **Transform data > Manage parameters**, set `DataFolder` to
your local folder, ending in a backslash, for example
`C:\Users\you\retail-inventory-decisions\data\processed\`.

## Pages

| Page | Question it answers | Visuals |
| --- | --- | --- |
| Reorder now | What needs attention today? | Cards: products below reorder point, shortfall units, products tracked. Table of products at or below their reorder point, largest shortfall first |
| Stockouts vs holding cost | How much buffer stock is worth it? | Stacked columns of holding cost + lost margin by service level, stockout-days line, trade-off table, recommendation |
| Stock over time | What does the policy actually do? | Product and service-level slicers, stock on hand vs reorder point through 2011, daily lost sales |
| Sales trend | What is real demand like? | Revenue, units and products cards, revenue by month, units by product, year slicer |

## Model

- **Tables:** Products, Sales, Policy, Stock Simulation, Backtest Summary, Reorder Status (all
  loaded from `data/processed/`), plus Calendar, Service Level and Key Measures (built in DAX).
- **Relationships:** single-direction, one-to-many from each fact table to Products, Calendar and
  Service Level. Service levels join on an integer key (80, 90, 95, 98, 99), not on a decimal.
- **Measures:** 15, each with a description, in the Key Measures table. Implicit measures are
  turned off, so every number on the report comes from a named, documented measure.

## How it was checked before it reached Power BI Desktop

- Every JSON file was validated against
  [Microsoft's published Power BI schemas](https://github.com/microsoft/json-schemas)
  (`python powerbi/check_pbip.py path/to/json-schemas`). The checker was itself tested by planting
  mistakes and confirming each one was caught.
- Every field a visual uses (45 references) is checked against the tables, columns and measures
  in the model, both in the generator and in the tests.
- The TMDL follows the structure of a project exported by Power BI Desktop.
- A test regenerates the project and fails if any committed file differs from the generator's
  output.

What could not be checked here: rendering, and DAX and Power Query evaluation, which need Power
BI Desktop. Open it once and compare with the table above.

## Change the dashboard

Edit `powerbi/build_pbip.py`, then run:

```
python powerbi/build_pbip.py
python -m unittest tests.test_powerbi
```

Changes made by hand in Power BI Desktop are saved into the same files. If you edit in Desktop,
either stop using the generator or carry the change back into it, because rerunning it overwrites
the `definition` folders.
